| 现象                       | 检查项                                 | 需要保留的证据                        |
| -------------------------- | ---------------------------------------- | ------------------------------------- |
| 找不到设备                 | 数据线、供电、VID/PID、枚举、权限        | USB 描述符和物理端口路径              |
| 视频接口 busy              | 已有程序或内核驱动持有接口               | 占用进程、驱动绑定；不直接 reset 整机 |
| Protocol 无应答            | 是否选到了 Debug CDC、波特率、流控、独占 | 接口号、TX/RX 原始字节、时间          |
| VT12 没有 UDP              | 地址/掩码、无线状态、防火墙、监听占用    | 网卡身份、UDP 计数、09/40 状态        |
| VT12 有包但花屏            | SPS/PPS/IDR、序号缺口、缓存丢弃          | 原始 udpbin、解码日志、损坏标记       |
| VT13 有字节无画面          | 是否错误剥头、参数集、IRAP、关键帧控制   | h265、请求/取消时间、NAL 类型         |
| 改信道后仍无图             | 写入/ACK/回读/无线/视频逐层区分          | 请求序号、ACK、后续推送及新视频包     |
| 串口写成功但外部设备无数据 | 设备系列、命令、长度、4B 尾部、各层 CRC  | 主机完整帧与发送端 UART 原始接收      |
| 延迟逐渐增长               | 接收线程阻塞、解码积压、显示队列         | 队列深度、解码/显示帧数、主机帧龄     |

## 一次硬件验证应记录什么

1. 发送端/接收端型号、可读取的固件版本、USB 描述符、主机系统和依赖版本。
2. 视频先做持续接收：字节数、帧数、分辨率、解码错误、损坏标记、序号缺口/超时。
3. 对冷启动、中途接入、USB 拔插、无线中断分别检查恢复；记录关键帧是否真正到达。
4. 配置实验保存发送、匹配 ACK、状态回读，明确是否需要重新枚举及配置是否掉电保持。
5. 自定义数据分别测试上下行，逐字节比较主机 payload 与对端收到的内容，分别记录两个方向的结果。
6. 多设备与端口占用测试确认不会误选、不会跨进程交错写串口。
