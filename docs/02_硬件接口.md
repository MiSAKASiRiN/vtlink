# 硬件接口与通路

[返回开发包](../README.md)

## VT02 / VT12

```text
视频源 → VT02 → 无线链路 → VT12 → USB RNDIS → IPv4/UDP → H.264 解码
外部 UART设备 ↔ VT02 ↔ 无线链路 ↔ VT12 CDC ↔ 主机数据接口
```

VT12 USB 标识 `2CA3:001F`，已有描述符显示产品名称 `pigeon`。RNDIS 为接口 0/1；接口 2 为存储功能；接口 3 为另外的 vendor bulk 功能，记录过 IN `0x84`/OUT `0x03`。视频通过 RNDIS 接口接收。CDC Control 为接口 4，Data 为接口 5。

用户态 RNDIS 参考读取 IN `0x81`、写入 OUT `0x01`。OUT 用于以太网 ARP 等网络维护，业务数据通过 CDC 串口发送。系统网卡模式无需自行访问这些端点。

主机 `192.168.42.105/24`，设备 `192.168.42.2`，视频目标 UDP 8080。手动配置只作用于已确认身份的专用网卡。分别读取并记录 USB 描述符中的 `bcdDevice`、接收端模式值和发送端固件版本。

## VT03 / VT13

```text
视频源 → VT03 → 无线链路 → VT13 interface 0 / IN 81 → HEVC 解码
外部 UART设备 ↔ VT03 ↔ 无线链路 ↔ VT13 Protocol CDC ↔ 主机数据接口
```

VT13 USB 标识 `2CA3:1020`，已有产品名称为 `C5`。Configuration 1，interface 0 alternate 0 的 Bulk IN `0x81` 为视频，OUT `0x01` 不用于本包视频控制。Interface 1 的 IN `0x82`/OUT `0x02` 为另外的数据/日志通路。

Protocol CDC Control 为接口 2、Data 为接口 3；Debug CDC Control 为接口 4、Data 为接口 5。macOS IORegistry 可能按 Data 接口号识别串口，Linux sysfs/Windows 功能节点通常对应 Control 接口；因此“macOS 接口 3”和“Windows MI_02”可以指同一个 Protocol 通路。

两代主机 Protocol CDC 均使用 961200、8N1、无流控。示例先关闭 DTR/RTS 再打开串口。发送端外部 UART 按对应硬件型号单独配置。

## 发送端 UART 与电气连接

VT02 单机型的既有硬件资料记录了 115200、8N1、无流控的信道配置 UART，以及 `0x0F01` 设置、`0x0F02` 查询。SDK 保留对应字节生成函数；此包没有对发送端 UART 自动探测、刷写或实际发送。

VT03 外部 UART 的波特率、连接器针脚、电平和供电要求按实际硬件版本配置，接线前查阅对应型号的接口定义。

FTDI USB 串口是外部设备接入主机的可选方式，与接收端 Protocol CDC、发送端 UART 是三个不同位置。接线前核对各接口的 TTL/RS232 等电平类型、公共地、TX/RX 方向和供电规范。

## 资源所有权

- 同一 Protocol CDC 由一个进程负责，配置、关键帧和数据写入统一串行化。
- 同一视频 USB 接口只能由一个接收会话 claim；退出时释放。
- 默认不 reset USB、不切换 configuration，不自动解绑内核驱动。
- 接收端报告的占位序列号不保证唯一。多设备环境同时记录物理 USB 路径。
- USB 拔插后重新枚举，不复用旧 COM/tty 路径的身份判断。
