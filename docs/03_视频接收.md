# 视频接收、同步与恢复

[返回开发包](../README.md)

## VT12：UDP/H.264

系统网卡或用户态 RNDIS 最终均产生完整 UDP datagram。先过滤来源 `192.168.42.2` 和目标端口 8080，再处理每个 datagram 的 8 字节前导。已保存样本首字节为 `0x47`，第 1 字节可用于按 uint8 回绕统计序号缺口。其余前导字节按原始数据保留。

剥除 8 字节后为 H.264 Annex B。当前参考接收器要求码流以三字节或四字节起始码开始；这属于已观测固件的形态约束。若目标固件改变 datagram 边界，先保存原包，再按实际边界调整分帧规则。

RNDIS 数据需要跨 USB read 缓存和重组。用户态路径先按 RNDIS message length 重组，再根据 data offset/length 取 Ethernet，处理 ARP、IPv4 和 IP 分片，最后提取 UDP。IPv4 大包按分片偏移重组为完整 UDP datagram。

H.264 SPS/PPS 是参数集，IDR 提供解码恢复点。建议在发送端开始出流前启动接收；晚加入收到预测帧时，即使解码器输出画面，也可能仍带恢复/损坏标记。VT12 接收流程等待发送端输出 SPS/PPS 和 IDR。

## VT13：USB/HEVC

Interface 0、Bulk IN `0x81` 返回连续 HEVC Annex B 字节流。读取结果按顺序拼接，再通过 Annex B 起始码提取完整 NAL，缓存末尾未完成的数据。

NAL type 为第一个头字节 `(byte >> 1) & 0x3F`。同步模块收集 VPS/SPS/PPS（32/33/34），等待 IRAP（16–21）且 `first_slice_segment_in_pic_flag` 为 1，然后把参数集和该图像交给新解码器。起始码本身也可能跨两次读取。

在 USB 持续读取后，通过 Protocol CDC 发送 DUML `01/01`、receiver `0x0E`：

| 动作 | 10 字节 payload |
|---|---|
| 请求关键帧 | `00 00 00 00 00 24 00 00 00 24` |
| 取消请求 | `00 00 00 00 00 04 00 00 00 04` |

参考等待约 150 ms 后取消；预览程序的恢复逻辑在仍未同步时约每 2 秒重试。这些间隔是本包预览程序采用的恢复参数。取消属于完整请求流程，进程正常退出时应尽力完成。

## 缓存与实时显示

接收、解码、显示分别运行。解码前的压缩流需要保持连续；队列溢出时记录码流不连续事件，清理积压并重建同步。显示层可只保留最新解码图像，避免显示积压拖慢接收。

分辨率由参数集和解码结果确定。裸流播放帧率由播放器配置；相机帧率通过采集时间与帧计数测量。性能报告分别记录主机解码帧龄、软件显示帧率和端到端延迟。

建议至少记录：接收字节、UDP 序号缺口或 USB 超时、队列溢出、关键帧数、解码异常、FFmpeg 严重日志、损坏标记、最新帧时间。画面停顿时标记旧帧，并分别统计接收字节和成功解码的新帧。

## 离线样本

VT12 完整启动样本：`samples/vt12-startup.udpbin`。格式为文件头 `VT12UDP1`，之后每条 `<d4sHI`（18 字节：相对时间、IPv4、端口、长度）及对应 UDP payload。

VT13 样本：`samples/vt13-video.h265`。它包含可同步的参数集和关键帧。实时增量解码会缓存最后尚未完成的 NAL/packet；完整 EOF 刷新还会输出缓存中的末尾帧，计数通常相差 1–2 帧。

统一执行 `python tools/validate_offline.py` 可复核两套样本，报告保留实际依赖版本和当前得到的帧数。
